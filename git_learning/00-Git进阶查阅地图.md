# 00 Git 进阶查阅地图

这套笔记不再按“从零入门”来写，而是按问题模块整理。

你已经走通过一次完整闭环：连接远程仓库、创建分支、提交、push、PR、merge、删除分支。接下来学习 Git，重点不是再背 `add commit push`，而是在遇到具体问题时知道去查哪个模块。

## 模块目录

| 文件 | 适合什么时候看 |
| --- | --- |
| `01-status-diff-add-commit.md` | 想确认改了什么、该不该提交、如何组织一次 commit |
| `02-log-show-blame.md` | 想看历史、找某次提交、查某行代码是谁改的 |
| `03-restore-reset-reflog.md` | 改错了、提交错了、想撤回、想救回误操作 |
| `04-branch-remote-pr-cleanup.md` | 分支、远程仓库、push/pull、PR 后清理分支 |
| `05-merge-rebase-conflict.md` | 合并、变基、同步 main、解决冲突 |
| `06-stash-cherry-pick-tag.md` | 临时保存、挑提交、打版本标签 |
| `07-gitignore-large-files.md` | 忽略文件、大文件误提交、数据集和模型文件处理 |

## 建议使用方式

平时不用通读。

遇到问题时按场景查：

- “我现在改了哪些东西？”看 `01`
- “我之前哪次提交改了这个？”看 `02`
- “我后悔了，想撤回。”看 `03`
- “我 push 后 PR 合并完了，分支怎么删？”看 `04`
- “main 更新了，我的 feature 分支怎么跟上？”看 `05`
- “我手上改了一半，但要临时切分支。”看 `06`
- “大文件又被 Git 跟踪了。”看 `07`

## Git 思维升级

入门阶段关注命令：

```text
add -> commit -> push
```

进阶阶段关注状态：

```text
我在哪个分支？
我本地和远程差几步？
哪些内容在工作区？
哪些内容在暂存区？
哪些内容已经进入历史？
这次操作会不会改历史？
```

判断一个 Git 操作是否危险，主要看两点：

1. 它会不会影响已经提交的历史。
2. 它会不会删除工作区里的本地修改。

不确定时先执行：

```bash
git status
git log --oneline --decorate --graph -10
```

这两个命令先看清楚，再决定下一步。
